## Composition Execution Architecture

### CompositionExecutor Integration
**Location**: `src/apps/tool-gateway.ts:1302-1391`

```typescript
private async executeComposition(
  composition: any,
  args: unknown,
  extra?: { sessionId?: string; userRoles?: string[]; correlationId?: string }
): Promise<any> {
  // Build execution context
  const executionContext = {
    input: args,
    context: {},
    sessionId,
    correlationId,
    userRoles: extra?.userRoles || ['user'],
  };

  // Execute composition
  const result = await this.compositionExecutor.execute(composition, executionContext);

  // Handle success/error
  if (result.status === 'success') {
    return {
      content: [{ type: 'text', text: JSON.stringify(result.output, null, 2) }],
    };
  } else {
    return {
      content: [{ type: 'text', text: `Composition execution failed: ${result.error}` }],
      isError: true,
    };
  }
}
```

**Key Components:**
1. **CompositionExecutor** - External component that executes multi-step workflows
2. **ExecutionContext** - Contains input, context, sessionId, correlationId, userRoles
3. **Result Format** - `{ status, output, executionTime, stepsExecuted, error, errorCode }`

## Composition Registration Pattern

### Tool Registration
**Location**: Lines 1253-1296

```typescript
private async registerCompositionTool(composition: any): Promise<void> {
  const toolId = composition.metadata.name;
  const description = composition.metadata.description || `Composition: ${toolId}`;
  const jsonSchema = composition.spec.inputSchema;

  // 1. Register in ToolRegistry (internal resolution)
  this.registry.registerTool({
    id: toolId,
    displayName: toolId,
    description,
    inputSchema: jsonSchema,  // JSON Schema
    source: 'composition',
    execute: async (args: unknown, extra?: any) => {
      return await this.executeComposition(composition, args, extra);
    },
  });

  // 2. Register via Bit MCP interface (MCP client exposure)
  this.registerTool(
    toolId,
    description,
    standardSchema,  // Standard Schema adapter
    async (args: unknown, extra?: any) => {
      return await this.executeComposition(composition, args, extra);
    }
  );
}
```

**Dual Registration:**
- ToolRegistry (internal): Uses JSON Schema
- MCP Server (external): Uses Standard Schema adapter

## RBAC Considerations (T3.3 Focus)

### Current State
**tool-gateway.ts** does NOT implement per-step RBAC validation for compositions. The RBAC validation happens at the composition level (when the composition tool is invoked), but NOT for each constituent tool within the composition.

**Security Gap:**
A composition registered by a premium model could invoke tools that are denied to basic models. This is privilege escalation.

### Required Implementation (T3.3)
```typescript
private async executeComposition(
  tool: ToolRegistryDocument,
  args: unknown,
  context: ToolExecutionContext
): Promise<ToolResult> {
  // 1. Load composition definition
  const composition = await this.compositionRegistry.get(tool.id);

  // 2. Extract constituent tool IDs from composition.spec.steps
  const constituentToolIds = extractToolIdsFromSteps(composition.spec.steps);

  // 3. Validate RBAC for EACH constituent tool against INVOKING model
  for (const constituentToolId of constituentToolIds) {
    const rbacResult = await this.validateToolAccess(
      constituentToolId,
      context.userId,
      context.modelId,  // INVOKING model, not registering model
      context.userRoles
    );

    if (!rbacResult.allowed) {
      throw new Error(`Composition denied: constituent tool ${constituentToolId} not allowed for model ${context.modelId}`);
    }
  }

  // 4. Execute composition (all tools validated)
  const result = await this.compositionExecutor.execute(composition, executionContext);

  return result;
}
```

**Critical Principle:**
> Validate against the **invoking model** (the model calling the composition), NOT the **registering model** (the model that created the composition).
