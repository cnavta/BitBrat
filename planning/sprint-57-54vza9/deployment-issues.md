# Sprint 57 Deployment Issues

## Issue 1: Incorrect firebase-emulator Dependency (RESOLVED)

**Status**: ✅ **RESOLVED** - 2026-11-09
**Priority**: High
**Affects**: T5.1 (Deploy to staging)

### Problem

Bulk deployment to staging failed with:

```
service "tool-orchestrator" depends on undefined service "firebase-emulator": invalid compose project
```

### Root Cause

The `tool-orchestrator.compose.yaml` file incorrectly depended on the deprecated `firebase-emulator` service instead of `postgres`. This was a configuration error from service creation - the service was always intended to use PostgreSQL (via DocumentStore), not Firestore.

### Resolution

**File**: `infrastructure/docker-compose/services/tool-orchestrator.compose.yaml`

Changed dependency from:
```yaml
depends_on:
  nats:
    condition: service_healthy
  firebase-emulator:  # WRONG - deprecated
    condition: service_healthy
```

To:
```yaml
depends_on:
  postgres:  # CORRECT - matches DocumentStore backend
    condition: service_healthy
  nats:
    condition: service_healthy
```

This now matches the standard pattern used by all other PostgreSQL-backed services (auth, llm-bot, tool-gateway, etc.).

## Issue 1b: Outdated Infrastructure Pattern (RESOLVED)

**Status**: ✅ **RESOLVED** - 2026-11-09
**Priority**: High
**Affects**: T5.1 (Deploy to staging)

### Problem

After fixing the firebase-emulator dependency, deployment still failed with:

```
failed to solve: failed to read dockerfile: open Dockerfile.tool-orchestrator: no such file or directory
```

### Root Cause

The `brat bit create` command generated docker-compose configuration using outdated infrastructure patterns (pre-Sprint 375). The configuration referenced a service-specific `Dockerfile.tool-orchestrator` which doesn't exist, instead of using the modern shared `Dockerfile.service` approach.

**Old Pattern (Generated by `brat bit create`)**:
```yaml
build:
  context: .                              # ❌ Wrong: Current directory
  dockerfile: Dockerfile.tool-orchestrator # ❌ Wrong: Doesn't exist
ports:
  - "${TOOL_ORCHESTRATOR_HOST_PORT:-3000}:3000"  # ❌ Hardcoded port
```

### Resolution

**File**: `infrastructure/docker-compose/services/tool-orchestrator.compose.yaml`

Updated entire build configuration to Sprint 375 standard:

```yaml
build:
  context: ../..  # ✅ Repository root (for Dockerfile.base/Dockerfile.service)
  dockerfile: Dockerfile.service  # ✅ Shared Dockerfile
  args:
    BASE_IMAGE: bitbrat-base:${BITBRAT_VERSION:-latest}  # ✅ Sprint 375: Shared base image
    SERVICE_NAME: tool-orchestrator
    SERVICE_ENTRY: dist/apps/tool-orchestrator-service.js
    SERVICE_PORT: "3000"
environment:
  - MCP_AUTH_TOKEN=${MCP_AUTH_TOKEN}  # ✅ Standard MCP env var
ports:
  - "${TOOL_ORCHESTRATOR_HOST_PORT:-3001}:${SERVICE_PORT:-3000}"  # ✅ Uses build arg
```

**Additional Changes**:
- ✅ Added network alias: `tool-orchestrator.bitbrat.local`
- ✅ Updated healthcheck: `/healthz` endpoint, faster intervals (5s instead of 30s)
- ✅ Changed default host port: 3001 (matches pattern of other services)

**References**:
- Remediation Plan: `planning/sprint-57-54vza9/tool-orchestrator-infra-remediation.md`
- Bug Report: `bugs/2026-11-09-brat-bit-create-outdated-infra.md` (BUG-2026-11-09-003)

## Issue 2: Single-Service Deployment Fails for tool-orchestrator (KNOWN LIMITATION)

**Status**: Documented for future resolution
**Priority**: Medium
**Affects**: T5.1 (Deploy to agent-dev and validate)

### Problem

The `tool-orchestrator` service cannot be deployed in isolation using the current deployment tooling:

```
service "tool-orchestrator" depends on undefined service "nats": invalid compose project
```

### Root Cause

The tool-orchestrator service has dependencies on infrastructure services (NATS, PostgreSQL) that are not available when deploying a single service using the docker-compose strategy. The deployment command:

```bash
npm run brat -- bit deploy tool-orchestrator --context local
```

Attempts to deploy only the tool-orchestrator service but fails because:
1. NATS service is required (message bus dependency)
2. PostgreSQL is required (DocumentStore backend)
3. Single-service deployment strategy doesn't provision dependent infrastructure

### Attempted Solutions

1. ✗ Deploy to agent-dev context - Agent-dev provisioning has known issues
2. ✗ Deploy to local context - Fails with missing NATS dependency
