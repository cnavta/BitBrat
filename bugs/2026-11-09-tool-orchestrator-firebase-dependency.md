# Bug Report: tool-orchestrator Incorrectly Depends on Deprecated firebase-emulator

**Bug ID**: BUG-2026-11-09-001
**Severity**: High
**Status**: ✅ Fixed
**Reported**: 2026-11-09
**Fixed**: 2026-11-09
**Affects**: Sprint 57, tool-orchestrator service
**Component**: `brat bit create` template / docker-compose configuration

---

## Summary

The `tool-orchestrator` service was created with an incorrect dependency on the deprecated `firebase-emulator` service instead of `postgres`, causing all deployment attempts to fail with "invalid compose project" errors.

---

## Environment

- **Sprint**: Sprint 57 (Foundation - tool-orchestrator with Persistent Registries)
- **Service**: tool-orchestrator
- **Profile**: core
- **Backend**: PostgreSQL (via DocumentStore abstraction)
- **Deployment Context**: staging (also affects local, agent-dev)

---

## Problem Description

When attempting to deploy the newly created `tool-orchestrator` service to staging, the deployment failed with:

```
service "tool-orchestrator" depends on undefined service "firebase-emulator": invalid compose project
[docker-compose-strategy] Bulk deployment failed: Remote Docker command failed with exit code 1
```

This occurred during bulk deployment (`npm run brat -- bit deploy --all --context staging`) and would affect any deployment of this service.

---

## Root Cause

The `tool-orchestrator.compose.yaml` file generated by `brat bit create` contained an incorrect dependency on `firebase-emulator`:

```yaml
# INCORRECT (generated)
depends_on:
  nats:
    condition: service_healthy
  firebase-emulator:  # ❌ WRONG - deprecated service
    condition: service_healthy
```

**Why this is wrong**:
1. **Firebase/Firestore is deprecated** platform-wide (per CLAUDE.md: "PostgreSQL (default, platform-agnostic), Firestore (legacy, deprecated)")
2. **tool-orchestrator uses PostgreSQL** via `createDocumentStore()` - it was never designed to use Firestore
3. **firebase-emulator service doesn't exist** in staging or most execution contexts
4. **All other PostgreSQL-backed services** (auth, llm-bot, tool-gateway, etc.) correctly depend on `postgres`

---

## Steps to Reproduce

1. Create a new service using `brat bit create`:
   ```bash
   npm run brat -- bit create tool-orchestrator \
     --profile core \
     --exposure platform-only \
     --register --active
   ```

2. Implement service using PostgreSQL DocumentStore:
   ```typescript
   const store = await createDocumentStore(); // Uses PostgreSQL
   ```

3. Attempt deployment:
   ```bash
   npm run brat -- bit deploy tool-orchestrator --context staging
   # OR
   npm run brat -- bit deploy --all --context staging
   ```

4. **Result**: Deployment fails with "undefined service 'firebase-emulator'" error

---

## Expected Behavior

The generated `tool-orchestrator.compose.yaml` should depend on `postgres` (not `firebase-emulator`) to match:
- The actual backend implementation (PostgreSQL DocumentStore)
- Platform-wide deprecation of Firestore
- The standard pattern used by all other services

**Expected dependency configuration**:
```yaml
depends_on:
  postgres:  # ✅ CORRECT
    condition: service_healthy
  nats:
    condition: service_healthy
```

---

## Actual Behavior

The service was generated with a dependency on the deprecated `firebase-emulator` service, causing deployment failures in all contexts where firebase-emulator is not available (staging, production, most agent-dev contexts).

---

## Impact

- **Severity**: High - Blocks all deployments of the service
- **Scope**: Affected tool-orchestrator service created in Sprint 57
- **Workaround**: Manual fix required (edit compose file)
- **Potential Scope**: May affect other services created with `brat bit create --profile core`

---

## Fix Applied

**File**: `infrastructure/docker-compose/services/tool-orchestrator.compose.yaml`

```diff
  depends_on:
+   postgres:
+     condition: service_healthy
    nats:
      condition: service_healthy
-   firebase-emulator:
-     condition: service_healthy
```

**Commit**: Part of Sprint 57 deliverables

---

## Root Cause Analysis

The bug originates from the `brat bit create` command's docker-compose template generation logic. Likely causes:

1. **Outdated template**: The docker-compose template may reference deprecated firebase-emulator
2. **Profile-based logic error**: The `--profile core` flag may incorrectly select firebase template
3. **Default fallback**: Missing logic to detect DocumentStore backend and auto-select postgres

**Suspected code location**:
- `tools/brat/src/commands/bit/create.ts` (service creation)
- `tools/brat/src/templates/docker-compose.template.yaml` (if exists)
- `tools/brat/src/deployment/compose-generator.ts` (if exists)

## Prevention Recommendations

### 1. Update Service Creation Template

Ensure `brat bit create` generates the correct dependencies based on:
- **Backend type**: PostgreSQL → postgres dependency
- **Profile**: core services should default to postgres (not firebase)
- **Deprecated services**: Never generate dependencies on firebase-emulator

### 2. Add Validation Check

Add validation in `brat bit create` to:
- Detect if generated compose file references deprecated services
- Warn user if dependency doesn't match implementation
- Auto-correct known mismatches

### 3. Update Documentation

Add to `documentation/guides/creating-new-bits.md`:
- ✅ Verify generated docker-compose dependencies match your backend
- ✅ Use `postgres` for DocumentStore (default)
- ❌ Never use `firebase-emulator` (deprecated)

### 4. Regression Test

Add test case to validate:
```typescript
// Test: brat bit create with --profile core should generate postgres dependency
it('should generate postgres dependency for core profile', async () => {
  const result = await exec('npm run brat -- bit create test-service --profile core');
  const composeFile = readFile('infrastructure/docker-compose/services/test-service.compose.yaml');

  expect(composeFile).toContain('postgres:');
  expect(composeFile).not.toContain('firebase-emulator:');
});
```
